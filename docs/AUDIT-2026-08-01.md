## 1. Outage root cause

- Symptom: every tafsir query returns `{"error":"Verse X not found"}` (HTTP 404).
- Chain: `POST /tafsir` → `get_verse_from_firestore` (app.py:1264, DB `tafsir-db` in
  project `tafsir-simplified-6b262`) → `403 This API method requires billing to be
  enabled on project tafsir-simplified-6b262` → returns None → 404 at app.py:6945.
- Cloud Run error logs show this 403 continuously since at least 2026-07-29.
- `gcloud billing projects describe tafsir-simplified-6b262` → `billingEnabled: false`,
  no billing account. Infra project `tafsir-simplified` is fine (account
  `0152F9-4F49EC-74C075`, open).
- NOT the Gemini model: `gemini-2.5-flash` (deployed env) retires Oct 16 2026 (Gemini
  API) / Oct 20 2026 (Vertex). Endpoints not touching Firestore work fine today
  (`/health`, `/personas`, `/daily-verse` all 200).
- Fix: `gcloud billing projects link tafsir-simplified-6b262 --billing-account=0152F9-4F49EC-74C075`

## 4. Security findings (backend)

1. **`POST /cache/invalidate` (app.py:4058) — unauthenticated full cache wipe**
   (`{"type":"all","confirm":true}` deletes the whole `tafsir_cache` collection).
2. **`POST /cache/store` (:3924) — unauthenticated cache poisoning**: writes arbitrary
   JSON into the cache that `/tafsir` serves to all users.
3. **`POST /cache/prewarm` (:4007)** — unauthenticated LLM spend.
4. **`GET /debug/test/<query>` (:7229)** — unauthenticated, unmetered 65K-token
   generation; logs full prompt + response. Also `/debug/range-map`, `/debug/verse-metadata`.
5. **`POST /feedback/daily-summary` (:10112)** — open unless `FEEDBACK_CRON_SECRET` set;
   triggers SMTP email.
6. Rate limiting is in-memory per instance → with max-instances 10, effective limit is
   ~10× stated; resets on every cold start.
7. Frontend: `/shared/[id]` renders backend markdown through `rehype-raw` (raw HTML
   allowed) — stored-XSS path if any shared content is user-authored. No CSP headers.
8. Firebase web config hardcoded in bundle (normal for Firebase, but verify API-key
   referrer restrictions + Firestore rules; `firestore.rules` defaults to deny-all,
   consistent with server-only access).

## 5. Correctness bugs (backend)

1. **Malformed-LLM-output cache poisoning** — `extract_json_from_response` (:2879)
   returns a truthy fallback dict (:3026) on failure, so the `if not final_json` 500
   path (:7122) is unreachable; garbage (500 chars raw text, zero verses) is cached
   permanently in memory + Firestore. `/debug/test` (:7406) checks
   `metadata.extraction_error` correctly; production handler doesn't.
2. **Guest cache never hits** — :7013 overwrites guest profile with `{}`; write-key
   persona differs from read-key persona (also silently switches guest persona to
   practicing_muslim in the prompt). Every guest query = full LLM call + orphan doc.
3. **Timeout stack mismatch** — gunicorn `--timeout 120` < single Gemini call (120s) +
   retry sleeps (worst ~494s) vs Cloud Run 300s. Retried requests die at the worker.
4. `MAX_TOKENS` finish reason treated as success (:7109) → truncated JSON → bug #1 path.
5. :2910 `NameError` risk: `fixed_text` unbound if `fix_malformed_json` raises.
6. `data/verse_range_map.json` missing from repo → `load_range_map()` (:2649) always
   falls back to recomputation; advertised "validated map" never loads.
7. Two inconsistent cache-key schemes (memory :1324 vs Firestore :4155) — normalized
   differently, so tiers hit/miss independently.
8. Firestore `tafsir_cache` has **no TTL** (README claims 7-day cache — false); only
   version-string invalidation (`SCHOLARLY_PIPELINE_VERSION` = "12.0").
9. `extract_verse_range`/`extract_verse_reference_enhanced` computed 3× per request.
10. Dockerfile ignores `$PORT`; `--cpu 2` with `--workers 1` wastes a core; 8 threads =
    concurrency ceiling per instance.
11. `cryptography` missing from requirements.txt (imported app.py:14; only transitive).

## 8. Positives worth keeping

- Deterministic retrieval pipeline (precomputed plans + keyword routing) is fast, cheap,
  and reproducible — good call vs. runtime RAG for this content.
- Two-tier caching design (memory + Firestore w/ gzip) is sound; just fix keys/TTL/poisoning.
- iman_service.py is cleanly separated pure logic (2,107 lines, no I/O).
- Graceful degradation exists on several secondary LLM paths (guidance summarize,
  feedback enrich return input/None on failure).
- Auth decorators are consistently applied on user-data routes; Firestore rules default
  deny.

## 9. Cost notes

- Guest cache bug (§5.2) means every guest query is a paid 65K-maxToken 2.5-flash call.
- `/debug/test` + `/cache/prewarm` are unauthenticated LLM spend vectors.
- Possible idle vector-search index/endpoint in `tafsir-simplified` (check console —
  Matching Engine endpoints bill hourly even when unused).
- Firestore cache grows unboundedly (no TTL) + orphan guest docs.
